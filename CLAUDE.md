# TruthEngine Edu

Hackathon project ("AI for Good Vol2", challenge "TruthEngine for EdTech: Multi-Modal Cognitive Defense").
A tool that splits learning material into atomic claims, rates how reliable each claim is against trusted
OPEN sources, explains why, and names the manipulation trick used (invented source, cherry-picking,
emotional wording, absolute claims...). Teachers can upload their own trusted documents (knowledge base, tier 1D). Media checks are risk signals, not deepfake detection.
See README.md for the tier table, gates and aggregation formula.

## Stack
Python 3.12, uv, FastAPI, asyncio, httpx, pydantic v2, Claude Messages API via plain httpx (no anthropic SDK: its native DLLs are blocked by Windows Smart App Control), python-dotenv. pytest (asyncio_mode=auto), ruff.

## Layout
- `app/services/separator.py`: `Separator.separate(text) -> list[str]` (Claude-based, validated; `separate_detailed[_async]` returns claims, non-claims and coverage).
- `pipeline.py`: `run_pipeline(text) -> Report` = Separator -> `CheckTrustedSources.run_detailed_async` -> `Report`.
- `app/services/knowledge/store.py`: teacher knowledge base (RAG). `KnowledgeStore` saves uploads under `data/knowledge/`
  (git-ignored), chunks them (pypdf for PDF) and searches with pure-Python BM25: no vector DB, native DLLs are blocked on our
  Windows laptops. `truthengine/sources/knowledge.py` turns hits into tier-1D `Evidence`; API: `GET/POST /sources`,
  `DELETE /sources/{id}`, `GET /sources/{id}/file`; UI: the "Trusted sources" expander in `app.py`.
- `app/services/trusted_sources.py`: `CheckTrustedSources`, the public facade. Sync `check` / `run` / `run_detailed`
  (use asyncio.run), async `check_async` / `run_async` / `run_detailed_async`. Takes `engine_factory` for tests.
- `app/services/truthengine/`: the engine.
  - `engine.py` `TruthEngine`: async context manager. Per claim: planner -> sources in parallel -> judge -> gates -> aggregate.
  - `config.py`: keys, `TIER_BASE`, `TIER_CAP`, `DOMAIN_TIERS`, `TRUSTED_WEB_DOMAINS`, thresholds. Tune weights here only.
  - `sources/`: one class per source, each returns `list[Evidence]`. Crossref is used for the citation-exists gate (G1).
- `api.py` (FastAPI `POST /analyze` -> `Report`), `analyzer.py` (runs `pipeline.run_pipeline` with mock fallback),
  `schemas.py` (`Report` contract shared by backend, front end and pipeline; don't rename fields), `app.py` (Streamlit UI),
  `mock_data.py` (fallback report and demo inputs).
- `eval/run_eval.py`: metrics against hand-written gold data. `scripts/demo.py`: live smoke test.

## Rules (do not break)
- The LLM is never a source of evidence: evidence text must come from a real fetch (API or retrieved web snippet).
- Every supporting/contradicting piece of evidence needs a verbatim quote that exists in the fetched text (`gates.quote_gate`).
- Gate `fail` -> weight 0. `unknown` -> weight x UNKNOWN_GATE_FACTOR. Copies from one origin count once (`Evidence.group_key`).
- "unverifiable" (score 0.5) is a valid answer; never invent evidence to avoid it.
- Keep claim context: qualifiers ("may", "some"), attribution ("according to X"), scope must survive extraction and judging.
- All network I/O is async. Sources run concurrently with `asyncio.gather(..., return_exceptions=True)`; one failing source
  must not fail the claim, one failing claim must not fail the batch. Respect the semaphores in config.
- Loop-bound objects (httpx/Anthropic clients, semaphores) are created in `TruthEngine.__aenter__`, never at import or in `__init__`.
- Score scale used by eval: >= 0.75 supported, <= 0.25 refuted, otherwise not enough evidence.
- Gold eval data is written by hand, never generated by the model the system uses.
- Uploaded teacher documents are evidence, not verdicts: they pass the same judge, quote gate and aggregation as any source.
- Never commit `.env`, API keys or `data/` (uploaded documents).

## Code style
ruff (`ruff.toml`): single quotes, line length 140, 2 blank lines after imports, `from __future__ import annotations`.
Tests must not hit the network: inject a fake engine via `engine_factory` or test gates/scoring directly.

## Commands
- `uv sync`
- `uv run pytest`
- `uv run ruff check . && uv run ruff format .`
- `uv run python scripts/demo.py` (needs ANTHROPIC_API_KEY in .env)
- `uv run python eval/run_eval.py`
- `uv run uvicorn api:app --port 8000` (backend) and `uv run streamlit run app.py` (front end)
- `docker compose up --build` (backend :8000 + front end :8501; demo mode without ANTHROPIC_API_KEY)
